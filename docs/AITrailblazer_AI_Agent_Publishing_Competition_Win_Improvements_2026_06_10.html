Improvements to Win the Google Cloud Rapid Agent Hackathon (MongoDB Track)

Official Requirements (Condensed from Captured Rules + Project Sources)

Core Mandate

Build a functional agent powered by Gemini + Google Cloud Agent Builder that integrates a Partner MCP server (MongoDB track) to solve a real challenge. Must use only Google Cloud + the chosen Partner’s products. No competing cloud platforms or non-permitted AI tools.

Strict AI Boundary

Only Google Cloud AI tools (Gemini on Agent Platform, etc.) + built-in AI features in the Partner product. All other AI coding assistants or services are prohibited for development and in the delivered project.

Submission Gates (Hard Pass/Fail in Stage 1)

  • Hosted project URL that works from a fresh/incognito browser.
  • Public GitHub repo containing all code + assets + clear run instructions.
  • Visible OSI-approved LICENSE at the top of the repo “About” section.
  • <3 minute public YouTube or Vimeo video (English or subtitles) showing the project actually functioning.
  • Text description covering features, technologies, data sources, findings & learnings.

Judging Criteria (Stage 2 — Equal Weight)

Technological Implementation: Quality of Google Cloud + Partner (MongoDB/MCP) integration and software craftsmanship.
Design: User experience and thoughtfulness of the interface.
Potential Impact: Scale of benefit to target communities (publishers, researchers).
Quality of the Idea: Creativity, uniqueness, and how well it solves the real challenge.

Project self-docs (Build Checklist, ExecPlan, Winning Spec) correctly narrow to a judge-legible vertical slice: TripCode → three-article River → MongoDB collections + official MCP proof → Gemini synthesis → second-turn session memory, all exposed in /v1/judge-demo with 7 panels, 6 collections, 3 verified live flows, and runtime proof statuses.

STRONG

Self-Contained Runtime (Major Recent Win)

P0 • Submission Gate

Produce the 3-Minute Video Immediately

Follow the exact shot list already written in the Build Checklist (0:00 hook → TripCode input → Mongo collections/MCP proof → Gemini answer → River traversal → second-turn memory without re-entering TripCode → close with hosted URL, public repo, OSI license, MongoDB track). Impact: Critical gate • Effort: Low–Medium (script + screen record)

P1 • Design + Idea Quality

Turn index.html into a Judge-Friendly Interactive Demo

The current custom-element landing is good. Add a prominent “Try it live” section with a TripCode input (default HUT-RIVER-001) that calls the hosted /v1/judge-demo or /resolve and renders the River nodes, claims, MCP evidence, Gemini text, and runtime proof panel in a clean visual layout (reuse the existing asset image and the proof structure). This gives judges an immediate delightful experience without curl or reading JSON.

Impact: High on Design & perceived quality • Effort: Medium

P1 • Hosted Verification

Fresh-Browser + Full Proof Validation

From a completely incognito browser + another machine if possible, open the referenced Cloud Run URL, exercise the three flows via the public surface or direct calls, and capture screenshots + the exact JSON from /v1/judge-demo showing all panels green, collections seeded/visible, MCP “live invoked”, and second-turn working. Update README.html and the public index with the evidence links.

Impact: Eliminates Stage 1 risk • Effort: Low

P2 • Track Differentiation

Complete One Atlas-backed Run (or have it ready)

Create the Secret (if not done), run make atlas-check locally against a real Atlas Free string, then make deploy-atlas. Even if the primary demo stays on embedded for reliability, having a verifiable “Atlas mode” deployment + a note in the description that the same code runs against managed Atlas gives strong MongoDB-track positioning without risking the deadline.

Impact: Medium–High for track judges • Effort: Medium (one secret + deploy)

P2 • Narrative & Learnings

Strengthen Submission Description & Repo README

In the Devpost text description and the top of README.html, explicitly call out the engineering insight (“self-contained embedded MongoDB + official MCP inside Cloud Run for zero-friction judging, with a clean Secret-Manager upgrade path to Atlas”), the research value of Rivers + TripCodes for publication memory, and concrete learnings (HTTP transport quirks of the official MCP, seeding strategy, readiness waits, etc.). Judges love documented findings.

Impact: High on “learnings” + Idea Quality • Effort: Low
